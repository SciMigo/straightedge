Dataflow, executed

How data actually moves through an accelerator and across a cluster — the mechanisms everyone draws as a static grid with arrows, and nobody runs. Each post is a simulation you can execute, animated from the simulation rather than illustrated beside it.

Every claim on screen is asserted in the code that draws it Scenes live in examples/ and re-render from source

A diagram of a systolic array can have the wrong schedule and look perfect. A Gantt chart of GPipe can put a backward pass one cycle early and nobody will notice, because nothing in the drawing is checked against anything. These posts take the opposite approach: the mechanism is simulated first, the picture is a consequence of the simulation, and the numbers on screen are counted from the run rather than typed in. A scene whose claim stops being true fails to render.

  1. The pipeline bubble 1F1B doesn't fix

    GPipe and 1F1B finish on the same cycle and idle for the same number of stage-slots. What 1F1B buys is activation memory — 23 sets against 6 — which is the number that decides whether a model fits.

    Pipeline parallelism

  2. Why the systolic array feeds itself diagonally

    The skew is not a convention. Entries entering on cycle t are exactly the anti-diagonal, because that is the only arrival time at which a multiply meets the running sum it belongs to — and each weight is then read from SRAM once instead of once per output.

    Systolic dataflow

  3. Ring all-reduce: the bytes per rank don't grow

    Reduce-scatter then all-gather, executed chunk by chunk. Each rank sends under 2D regardless of ring size; what grows with the ring is the number of serial hops, which is a latency story rather than a bandwidth one.

    Collectives

  4. Interleaved pipelines: the bubble that does move

    Splitting each device's layers into several non-contiguous chunks genuinely shrinks the bubble, and pays for it in cross-device traffic. Same treatment: simulated, measured, animated.
